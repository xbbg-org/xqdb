## Fixed — the last receive-side allocations that could abort the process

0.1.5 made the allocations that dominate a large q response fallible, so a result
too big for the machine returns an error rather than killing the host process.
Four smaller per-element sites were missed and are fixed here:

- Dictionary key strings, copied one per entry.
- String values decoded through `K::try_from_any_value`, one per element of a
  dictionary or mixed list.
- Symbol atoms.
- The column vector handed to the DataFrame constructor.

Each is individually small, but a list decodes one per element and the aggregate
scales with the payload, so a large enough frame could still reach Rust's
aborting allocator instead of returning `XqdbError`. Every allocation on the
receive path sized from wire data is now fallible.

No API, wire-format or behavioural change beyond the failure mode: work that
succeeded in 0.1.5 succeeds identically here.

## Note on 0.1.5

The 0.1.5 npm packages published successfully, but the release job failed its
post-publish readability check while the registry was still propagating, so no
GitHub Release was created for that tag and the Python distribution was never
published. `docs/release-notes/v0.1.5.md` has been corrected: it claimed every
process-sized allocation was fallible, which was true only of the sites listed
there. Users on 0.1.5 lose nothing by staying there except the four sites above.
